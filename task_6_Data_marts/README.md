# Task 6. Data Mart Repository

Решение создает схему `dmr` и витрину `dmr.analytics_student_performance`
с агрегированными показателями активности и успеваемости студентов.

## Источники данных

- `public.user_logs` - недельные агрегаты активности студентов по курсам.
- `public.departments` - справочник кафедр.

## Что считает витрина

- Итоговые события за семестр: `SUM(s_all)`.
- Средние события в неделю: `AVG(s_all)`.
- Просмотры курса, тестов, модулей и отправки заданий: суммы соответствующих недельных полей.
- Пиковая неделя активности: неделя с максимальным `s_all`; при равенстве берется меньший номер недели.
- Коэффициент стабильности: `1 - STDDEV_POP(s_all) / AVG(s_all)`, ограниченный диапазоном от `0` до `1`.
- Категория активности:
  - `низкая` - меньше 5 событий в неделю;
  - `средняя` - от 5 до 19.99 событий в неделю;
  - `высокая` - 20 и больше событий в неделю.

## Запуск

```bash
python -m pip install -r requirements.txt
python main.py
```

Параметры подключения читаются из `.env` или переменных окружения:

- `DB_HOST`, по умолчанию `localhost`
- `DB_PORT`, по умолчанию `5432`
- `DB` или `DB_NAME`, по умолчанию `educational_portal`
- `DB_USER`, резервно `USER`
- `DB_PASSWORD`, резервно `PASSWORD`
